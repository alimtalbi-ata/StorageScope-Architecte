# StorageScope V6.208 — Empreinte exacte du snapshot CMDB

**Auteur : Abdelhalim Talbi — 24 octobre 2026.**

## Contexte et défaut couvert

La revue CMDB V6.197/V6.198 conserve les provenances déclarées par les enregistrements, mais ne permettait pas de relier de façon cryptographique un rapport au fichier JSON effectivement analysé. Deux fichiers JSON sémantiquement identiques, mais ayant des octets différents, restaient impossibles à distinguer dans la preuve.

## Correction

`review_cmdb_file` lit une seule fois le fichier en mode binaire (8 Mio maximum), valide le JSON UTF-8/BOM, puis calcule `SHA-256` sur **les mêmes octets**. Le rapport de revue et son export contiennent `snapshot_sha256` (64 caractères hexadécimaux) et `snapshot_size_bytes`. La page Diagnostic affiche l'empreinte intégrale. L'entrée n'est jamais modifiée et le rapport ne remplace jamais un fichier existant.

### Chaîne de preuve conceptuelle (pas une capture réelle)

`Snapshot CMDB (octets) → lecture bornée unique → parseur strict → réconciliation → rapport + SHA256 + taille → vue Diagnostic / export exclusif`

L'empreinte permet une **vérification d'intégrité**, pas une preuve d'authenticité du fournisseur, de la CMDB ou de l'heure de collecte. Les données peuvent rester incomplètes ou contradictoires ; aucune fusion automatique n'est autorisée. Ne pas utiliser `assessment=NO_CANDIDATES` comme preuve d'exhaustivité.

## Qualification reproductible

`python -m unittest discover -s 04-Tests-et-Qualification -p 'test_cmdb_snapshot_digest_v6208.py' -v`

Cas testés : BOM et espaces conservés dans l'empreinte, JSON équivalent aux octets différents, export exclusif, refus des clés dupliquées, aucune création de rapport sur entrée invalide. Les fixtures sont synthétiques. La CI gouvernance exécute ces tests sur Linux et Windows ; **elle ne remplace pas** les contrôles de compilation native PyInstaller/Inno Setup, installation, désinstallation, portable et SHA256 des binaires.

## Traçabilité des référentiels

ISO 42010 : traçabilité des éléments de preuve de la vue CMDB ; ITIL 4 : revue des informations de configuration ; ISO 27001/27040 : intégrité des preuves liées à l'infrastructure de stockage. Alignement méthodologique, non certification.

## Limites

Aucune capture réelle d'interface ou test UX humain n'a été produit par cette modification. La validation native Windows V6.208 reste à confirmer par les workflows et les artefacts de la branche.
