# StorageScope V6.201 — Offline vendor snapshot adapters

**Author:** Abdelhalim Talbi  
**Status:** feature branch / draft PR; not a qualified Windows installer release.

## Scope and boundary

A read-only normalization API and CLI for *operator-supplied* JSON snapshots from NetApp ONTAP, Dell PowerScale and Pure FlashBlade. This is **not** a live API collector, does not authenticate to any array, does not write CMDB records and does not establish service-level availability. Every input is explicitly identified by vendor, `source_ref` and UTC `collected_at`. Unsupported vendors fail closed. No automatic vendor detection or silent fallback.

## Data flow

```text
Offline vendor snapshot JSON (<=5 MB)
     -> strict JSON parser (reject duplicate keys, NaN, oversized input)
     -> vendor-specific field mapping + provenance checks
     -> identity and capacity validation + duplicate quarantine
     -> storagescope.storage-topology.v1 (NAS assets and shares)
     -> existing storage_path_risk_v6194.assess() (optional)
     -> new report JSON, created exclusively (no overwrite)
```

## Input contract

```json
{
  "schema": "storagescope.vendor-snapshot.v1",
  "vendor": "netapp_ontap",
  "source_ref": "lab-capture-001",
  "collected_at": "2026-10-23T20:00:00Z",
  "systems": [
    {"serial_number": "SN-1", "cluster_name": "array-1",
     "capacity_used_bytes": 85899345920, "capacity_total_bytes": 107374182400,
     "volumes": [{"uuid": "vol-1", "protocol": "NFS", "used_bytes": 10737418240, "quota_bytes": 21474836480}]}
  ]
}
```

For `dell_powerscale`, system keys are `serial`, `cluster`, `used_bytes`, `total_bytes`, `exports` and share key `id`. For `pure_flashblade`, system keys are `array_id`, `name`, `space_used_bytes`, `space_total_bytes`, `shares` and share key `id`. Protocols: `NFS` or `SMB`. Capacity numbers are nonnegative integer bytes; absent metrics remain unknown, never implicitly zero. The normalized schema uses GiB. Maximum 1,000 systems and 10,000 shares. System serial duplicates are quarantined; duplicate share identities quarantine that system's shares. Rejected records are visible in `rejected` and make assessment `INCOMPLETE`.

## Usage

```bash
python 03-Sources/vendor_snapshot_import_v6201.py snapshot.json normalized-report.json
python -m unittest discover -s 04-Tests-et-Qualification -p 'test_vendor_snapshot_import_v6201.py' -v
```

The output path **must not exist**. The module is importable as `normalize(snapshot)` and `load_snapshot(path)`. No network access. Snapshots and fixtures in tests are synthetic; no real device evidence is claimed.

## Architecture alignment and limitations

- **ISO 42010 / TOGAF:** separate collection adapter, canonical topology and analysis concerns; explicit provenance and architectural assumptions.
- **ArchiMate:** normalized NAS assets and shares are technology-layer elements; application/service relationships are not inferred.
- **ITIL 4 / CMDB:** no CI merge or automatic updates; human review remains required.
- **ISO 27001 / 27040:** bounded parsing, fail-closed identity checks, no credentials, read-only import, no overwrite.

**Limitations:** no live NetApp/Dell/Pure API connectivity, no SAN host paths in vendor snapshots, no verified GUI integration, no Windows installer rebuild or manual UX screenshot in this change. Existing V6.200 native Windows qualification does not qualify V6.201.
