## Défaut fonctionnel corrigé — UpgradeGate dans l'installateur

L'Inno Setup `02-Compilation-Windows/StorageScope.iss` utilisait `Flags: dontcopy` pour `StorageScope-UpgradeGate.exe`. Cela permettait l'extraction temporaire dans `PrepareToInstall`, **mais pas l'installation de l'exécutable** dans `{app}`. Or `qualifier-installation-windows.ps1` vérifie explicitement sa présence après installation. La nouvelle entrée `[Files]` installe le même binaire en plus de l'entrée `dontcopy`. Le contrôle préalable aux mises à niveau est préservé.

**Risque résiduel :** le compilateur Inno Setup et les tests d'installation sur Windows doivent confirmer le comportement réel. Ne pas déclarer l'installateur qualifié sur la seule inspection statique.

## Cause racine Windows identifiée après les 19 assertions

La CI #39955795595 a validé la suite historique (**1 409 tests, 0 échec, 0 erreur ; 8 tests imbriqués PASS**), puis PyInstaller a effectivement construit `StorageScope.exe` et `StorageScope-UpgradeGate.exe`. Le build a ensuite échoué sur **`EXE version probe not created`**.

Le processus graphique PyInstaller était lancé avec l'opérateur PowerShell `&`, susceptible de rendre la main avant la fin du processus GUI. Le journal montre la sortie du self-test du binaire **après** l'échec du contrôle de version : c'est une preuve directe de la course. Le correctif remplace ces deux appels par `Start-Process -Wait -PassThru`, contrôle le code de sortie et protège le chemin du fichier de version entre guillemets. Trois nouveaux tests protègent cette garantie. Il reste à vérifier la nouvelle CI et la compilation Inno Setup.

La modification de la condition du smoke test `gate_checked` a révélé un contrat V6.49 figé sur l'ancienne expression : ce test a été mis à jour pour exiger le nouveau contrôle **en plus** de l'installation, de la version et de la désinstallation.

## Nouveau jalon : PyInstaller + Inno Setup compilés, publication encore bloquée

La CI Windows #39956525427 a confirmé la suite historique verte, la compilation native des **deux exécutables PyInstaller**, la compilation **Inno Setup 6.7.1** de `StorageScope-Setup-v6.108.exe`, et la vérification du manifeste de l'installateur (26 742 343 octets, SHA-256 `04065dd2f28ed9fc2dc87ece3aadd89ce9a4293423fed1d404a753aef4f7162e`). Ces fichiers ont été construits dans l'environnement temporaire du runner, **pas publiés comme livrables qualifiés**.

Le build échoue ensuite dans `publish-transaction.py` : `Publication and staging must be separate directories`. Le moteur crée intentionnellement `02-Compilation-Windows/.publish-pending` comme enfant direct du répertoire de publication ; le garde de sécurité rejetait indistinctement toute imbrication. La correction n'autorise **que** l'enfant direct nommé `.publish-pending`, rejette les fichiers annexes et les chemins imbriqués arbitraires, conserve les sauvegardes/rollback et supprime uniquement le répertoire de staging devenu vide après un commit complet.

Quatre nouveaux tests couvrent la publication imbriquée autorisée, le refus des chemins arbitraires, le refus de contenu inattendu et le rollback après échec injecté. **Aucune qualification installateur/désinstallation/portable n'est encore acquise** ; la nouvelle CI est en cours.
